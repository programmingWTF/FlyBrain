# FlyBrain · Flappy —— 用真实果蝇脑玩 Flappy

把 **FlyWire FAFB v783 果蝇全脑连接组**（**144,837 神经元 / 15,023,799 突触**）
当成一个**完全冻结、零可学参数**的神经网络，去驱动一只小鸟飞过管子。

**不训练。** 用的是连接组里真实存在的一条逃逸反射通路：

```
视觉逼近  →  LC4（104 个）/ LPLC2（210 个）  →  DNp01（巨型纤维，2 个细胞）  →  拍翅
```

---

## 一句话结论

| 组（同参数、同 40 局） | 均分 | 拍翅次数 |
|---|---|---|
| **real**：真实接线 | **100.8** | 256 |
| **cut**：切断 LC4/LPLC2 → DNp01 | **0.00** | **0** |
| **shuffled**：同度分布随机重连 | **0.00** | **0** |

`cut` 与 `shuffled` 都是 **0 次拍翅** —— 脑子不再指挥翅膀。
这就是"分数必须穿过真实连接组"的硬证据。

## 怎么跑

**零第三方依赖**：只用 Python 标准库 `http.server` + 仓库自带的 three.js。
不需要装包、不需要 GPU、不需要联网。

```bash
cd flyflappy

# 全脑资产（144,837 神经元 / 1502 万突触，载入慢一些，但这是完整脑）
D:/Code/FlyBrain/env/python.exe demo/server.py --asset spiking_full
# 浏览器打开 http://127.0.0.1:8620/
```

Windows 下也可以直接双击 `demo/run_demo.bat`（关闭用 `demo/stop_demo.bat`）。

## 控制回路

| 环节 | 做法 |
|---|---|
| 仿真 | LIF 脉冲网络。`dt=0.02` `τ=0.1` `gain=3.0` `tonic=0.14` `threshold=1.0`，带 1.2 Hz / 0.22 幅度噪声 |
| 输入 | 把"缺口相对鸟的高低"映射到 **LC4 腹侧/背侧半群**（双向逼近反射），再加 LPLC2 角尺寸通道 |
| 输出 | **只读 DNp01 的膜电位**；过阈值就拍一次翅 |
| 可学参数 | **0 个** |

一个绕不开的量化事实：DNp01 每个 tick 需要
`need = (1−leak)·thr/gain = 0.06042` 的持续驱动，而它是**漏积分**的
（`leak = 0.81873`）—— 所以单次刺激不够，必须**持续**逼近才会发放。
整个控制回路的节奏都由这一条决定。

### 双向逼近反射

方向由**缺口在视野里的高低**决定：

- 缺口在上方 → 驱动 **腹侧** LC4 半群 → 爬升
- 缺口在下方 → 驱动 **背侧** LC4 半群 → 下潜

再加接近速度门控（地面只在下落时逼近、天花板只在上升时逼近）。
神经计算**全部在后端**，前端只算望远镜几何。

## 分数是怎么一步步上去的

离线评测台 `scripts/flappy_bench.py`，前几档 200 局/条件：

| 阶段 | 均分 | 中位 | 最高 | 做了什么 |
|---|---|---|---|---|
| 被动（不控） | 0.00 | 0 | 0 | 基线，鸟自由落体 |
| 单侧反射 | 1.54 | 1 | 8 | 只接一路（页面早期做法） |
| 腹侧 LPLC2 地面反射 | 2.44 | 2 | 13 | 抬起下界 |
| **双向逼近反射** | **7.20** | 5~6 | 26 | 缺口高就爬、低就潜 |
| **+ 按执行器带宽生成关卡** | **29.52** | 21 | 72 | 关卡变得**物理上可达** |
| **+ `dors_scale=0.35` / `vent_gain=2.0` / 首管余量** | **100.8** | 115 | 115 | 两个外部增益旋钮 + 第一根管子留够反应时间 |

> 最后一档是 40 局、`max_ticks=8000`（所以"最高 115"是被 tick 上限截断的，
> 不是真实上限）。前面几档是 200 局、`max_ticks=5000`。

**关卡可达性是执行器带宽卡死的**：管距 300 px / 240 px·s⁻¹ = 1.25 s，
而鸟的可持续爬升率只有约 **100 px/s**（`scripts/flappy_climb_rate.py` 实测），
所以一个间隔最多爬约 125 px。原来缺口跳变有 330 px 量程 ——
**超出的关卡无论如何都飞不进去**。把向上跳变限制在 40 px 以内（向下不设限）之后，
分数从 7.2 跳到 29.5。管宽、缺口高、管速、重力**一个都没改**。

## 碰撞判定：为什么它需要逐像素对账

游戏里"看着撞上了却不判失败"这个 bug 查了很久，根因是**像素与坐标混用**。
最终判定由**逐像素**对账定出：

```js
if (G.y - BIRD_R <= p.top + BIRD_R
    || G.y + BIRD_R >= p.top + GAP - BIRD_R - 1) return die('撞上管子');
```

推导依据（**闭区间像素**）：

- `fillRect(y, h)` 覆盖像素 `y … y+h-1`
- 上管覆盖像素 `[0, top+R]`、下管覆盖像素 `[top+GAP-R-1, …]`
- 鸟圆周覆盖像素 `[⌈y-R⌉, ⌊y+R⌋]`
- 两组像素行有交集 ⇔ 视觉重叠

要求"**只画不判**"与"**只判不画**"同时为 0。历史上错过两次，而且方向相反
（`<= / >=` 和 `< / >` 各差一段 `R`，实测都是"只画不判" 35~37 个 y）。

## 页面 vs 评测台：已定位的差距

**页面上只有 27 分，评测台 100+。** 差距已经定位清楚：**浏览器喂不动脑**。

144,837 神经元的完整脉冲脑，要 **50 req/s** 才是 1:1 实时，
而浏览器实测只能做到 **14.3 req/s**（Node 客户端 64.7 req/s，服务端并发 377 req/s）。
批大小提到 4 之后页面到 20.4 tick/s，但仍是"脑落后于物理"。

上面 `game_slack = 0.694 → 2.07` 就是这个现象的**受控复现**。

> **正解是把仿真搬到服务端**（浏览器只做渲染与输入），这是目前最大的一个待办。

## 诚实的边界

- **`dors_scale` / `vent_gain` 是外部手写旋钮**，不是连接组里的东西。
  它们调节"感觉信号有多强"，作用在**脑的输入端**；连接组内部结构没有改过。
- **模型时钟 `dt = 20 ms`**，而真实巨型纤维通路是 1.4–25 ms，
  所以**延迟类数字只能定性**。
- **LC4 的灵敏度 `s50` 是外部假设**（文献里没找到 LC4 的实测发放率），
  它可调、会改变触发早晚，但不改变"有阈值、且由那 102 条边携带"这个结论。
- **预测/前瞻类尝试全部失败**，已如实记为负结果（见上表）。
- `scripts/flappy_page_parity.py` 目前**继承了评测台的 `World`**，
  所以它的"比值 1.0"没有验证力，**需要重写**。

### 部署到服务器

看 [`DEPLOY.md`](DEPLOY.md)。一句话版 —— **仓库是自包含的**：`data/` 里三个文件
（`spiking_full.npz` 50 MB / `spiking_full.json` 226 KB / `coords.npz` 1.6 MB）已入库，
`three.js` 也在 `demo/vendor/` 里，所以：

```bash
pip install numpy pandas torch --index-url https://download.pytorch.org/whl/cpu
python demo/server.py --asset spiking_full --no-browser --port 8620
```

⚠️ **`--asset` 必须显式传 `spiking_full`**：默认值是 `spiking_circuit`，那个子图
不含 LC4/LPLC2，而 Flappy 的所有感觉输入都打在这两个群上 ——
用默认值的后果是**分数恒为 0，而且不报错**。

本机实测：启动 **4.7 s**、内存 **483 MB**、`/api/step` 中位 **27 ms**。
