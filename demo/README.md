# Flappy 演示（网页版）

用**真实果蝇全脑连接组**（FlyWire FAFB v783，144,837 神经元 / 1,502 万突触）
当作**冻结的、零可学参数的控制器**，去玩 Flappy。

## 怎么跑

```bash
# 依赖（CPU 版 torch 就够）
pip install numpy pandas torch --index-url https://download.pytorch.org/whl/cpu

# 起服务（资产默认就是 spiking_full）
python demo/server.py --no-browser --port 8620
# 浏览器打开 http://127.0.0.1:8620/
```

Windows 上也可以直接双击 `run_demo.bat`。

> **`--asset` 默认已是 `spiking_full`。** 这里曾经是个静默失败陷阱（默认到
> 不含 LC4/LPLC2 的子图 → 分数恒 0 且不报错），现在改成：传了不含关键群的
> 资产就在**启动时被拒绝**并说明原因。

零第三方前端依赖：只用 Python 标准库 `http.server` + 仓库自带的 three.js。
不需要联网、不需要 GPU。

## 架构：谁在算什么

这是理解这个 demo 最关键的一张表 —— 我在这上面反复栽过跟头：

| 环节 | 跑在哪 | 节拍 | 说明 |
|---|---|---|---|
| **脑**（144,837 神经元 LIF） | 服务端 | 固定 **50 Hz** | `Session._game_tick` |
| **游戏物理 + 碰撞 + 关卡生成** | 服务端 | 与脑 tick **严格 1:1** | `GameWorld.step`，同一进程同一把锁 |
| **渲染** | 浏览器 | 自己的帧率（实测 60fps） | `app.js`：只取状态 + 插值 |
| 输入（空格/点击） | 浏览器 → 服务端 | — | `POST /api/game/flap` |

### 为什么仿真在服务端

**"完全恒定 + 完全同步 + 流畅"这三条，在前端做不到。**
前端试过四种驱动方式，每种都实测过，每种都失败：

| # | 驱动方式 | 实测结果 |
|---|---|---|
| ① | 物理跟**墙钟**走 + 每帧消化 1 步 | 帧率 <50fps 就积压几十步，鸟控不住 |
| ② | 物理跟**帧率**走 | 帧率 11.5fps 时只有 12% 速度，飞不起来 |
| ③ | 物理跟**脑响应**走 | 速度 = HTTP 往返速度 → **时快时慢** |
| ④ | 固定节拍 + 决策队列预取 | 队列周期性见底，仍然抖 |

根因是结构性的：**游戏时钟必须挂在某个节奏上**，而浏览器里只有两个可选项，
页面内直接测量得到的结论是：

```
setTimeout(4)            → 29.8 次/s   （被浏览器压到 ~33ms）
requestAnimationFrame    → 28.2 次/s   （页签切到后台还会被完全暂停）
```

再加上 HTTP 往返 **中位 60ms / p90 86ms / 最快 4ms**（差十几倍）——
只要决策要靠一次跨进程往返拿到，时钟就一定是抖的。

搬到服务端之后，脑与物理在同一个进程里 1:1 锁步，没有任何网络或定时器节拍
进入游戏时钟；前端取状态取晚了只会让画面晚一点，**不会改变游戏速度**。

| 指标 | 前端自跑（④） | 服务端锁步（现在） |
|---|---|---|
| 仿真速率 | 14~32 步/秒（抖） | **50.0 步/秒（恒定，偏差 +0.1%）** |
| 渲染帧率 | 与游戏速度耦合 | **60 fps，与游戏速度无关** |
| 决策与物理 | 靠队列近似配对 | **同一进程内严格 1:1** |

### ⚠️ 服务端权威下最容易踩的两个坑

都是我实际踩过的，写下来免得重复：

1. **前端改状态会被覆盖。** 手动拍翅**不能**在前端改 `G.vy` ——
   下一次状态同步会把它冲掉。必须 `POST /api/game/flap` 让服务端执行。
2. **脑图会静默变空。** 3D 面板要的 `viz_spike` / `lit_spike` / `eff`
   原来由前端自己那次 `/api/step` 的响应提供；那条路没了之后，
   面板**不报错地变成空的**。现在这些量由 `/api/game/state` 一起发回来。

## 看什么

1. **左边的游戏**：鸟自己飞，不需要你操作。它撞了就重开，分数累计最高分。
2. **分数在涨**说明反射真的在控制高度 —— 这不是脚本，是 144,837 个 LIF 神经元
   每个 tick 算出来的结果，**零可学参数**。
3. **手动接管**：按空格或点画面，你可以自己拍翅，体感一下这个游戏有多难
   （比看数字直观）。
4. **右侧 3D 脑图**是按真实解剖坐标摆的：橙色 = LC4，红色 = DNp01，
   灰色背景点随全脑活动闪烁。拖拽旋转、滚轮缩放。
5. **下方的驱动曲线**：LC4 群的角尺寸驱动量。它越过红色虚线（阈值 r50）时
   DNp01 才会发放。
6. **换干预 = 换被试**：切到「cut」或「shuffled」会重建脑的连接。
   `cut`（切断 LC4/LPLC2 → DNp01）和 `shuffled`（同度分布随机重连）下
   鸟**一次都不拍翅**、直接落地 —— 这是"分数必须穿过真实连接组"的现场演示。

## 校验（都不影响运行时性能）

```bash
node demo/verify_server_collision.js      # 服务端判定的碰撞 == 前端画的管子（逐像素）
node demo/verify_pipe_visual.js           # 管子形状不变量
node demo/verify_bird_volume.js           # 画出来的鸟外接半径 == 判定半径
node demo/verify_page.js 40               # 浏览器验收：无异常 + 渲染帧率 + 服务端速率恒定
python scripts/verify_server_physics.py   # 服务端物理 vs 评测台物理，逐 tick 对账
node demo/check_syntax.mjs demo/app.js    # 语法（⚠️ 抓不到"调用了不存在的函数"）
```

`verify_page.js` 需要一个已经在跑的服务（默认 `http://127.0.0.1:8620/`）。

## 已知限制

- **`dors_scale` / `vent_gain` 是外部手写旋钮**，不是连接组里的东西。
  它们作用在**脑的输入端**（感觉信号有多强），连接组内部结构没有改过。
- **单例 `Session`**：多个浏览器窗口会看到**同一个游戏**、互相干扰。
  演示够用，**不适合对外公开**（无鉴权）。
- **持续占一个 CPU 核**（约 500 MB 内存）。闲置时也照跑，
  因为"随时打开页面都是活的"体验更好。
- **模型时钟 `dt = 20 ms`**，而真实巨型纤维通路是 1.4–25 ms，
  所以延迟类数字只能定性。
- 分数与评测台（100+）不是同一个量级：页面用**随机关卡**，
  评测台用**固定种子**做对照。要看可复现的分数请用 `scripts/flappy_bench.py`。
