# 逃跑反射可交互演示

## 怎么跑（三选一）

```bash
# A. 双击 Windows 资源管理器里的 run_demo.bat

# B. 命令行
cd /d/Code/FlyBrain/flyflappy
D:/Code/FlyBrain/env/python.exe demo/server.py
# 然后浏览器打开 http://127.0.0.1:8620/   （会自动尝试打开）

# C. 用未截断的全脑资产（144,837 神经元 / 1502 万突触，载入慢一些）
D:/Code/FlyBrain/env/python.exe demo/server.py --asset spiking_full
```

零第三方依赖：只用 Python 标准库 `http.server` + 仓库里已自带的 three.js。
不需要装包、不需要 GPU、不需要联网。

## 怎么玩（按这个顺序，效果最强）

1. **默认「反射镜」模式**：一个暗盘从 2.2 米外正对苍蝇逼近。看左下角那条橙色曲线
   （LC4 群发放率）往上爬，**越过红色虚线（实测阈值 r50 = 0.58）的那一刻**，
   逃逸指令神经元 DNp01 发放 → 屏幕上弹「逃!」。
   读数栏同时给出触发时的视觉角 θ、角扩张速度 dθ/dt、剩余碰撞时间 τ。
2. **右侧 3D 是按真实解剖坐标摆的**（FlyWire 骨架包围盒中心，不是螺旋点云）：
   橙色 = 104 个 LC4，红色 = 2 个 DNp01，青蓝 = DNp02/DNp04/DNp11，
   灰色背景点随全脑活动闪烁。拖拽旋转、滚轮缩放。
3. **点「切断 LC4→DNp01 那 102 条边」** ← 这是整个演示的高潮。
   苍蝇当场不再逃（实测：真实接线 13 逃 0 失；切断后 0 逃 27 失），
   但 LC4 照常发放、DNp04 照常活动 —— 说明瘫掉的原因就是那一条单突触通路。
4. 再点「全脑目标打乱（毁掉拓扑）」：整个下行系统彻底静默。
5. 「关掉抑制」：阈值从 0.583 降到 0.500，苍蝇**更早**开始逃 —— 抑制是门控。
6. 切到「Flappy」模式：同样的反射去驱动拍翅飞过管子。它**大概率会摔**。
   这不是 bug：反射是"逼近触发"的脉冲，不是高度控制器。

## 三个模式

| 模式 | 给刺激的方式 | 结果 |
|---|---|---|
| **Flappy**（默认） | 苍蝇评估**最近的那个碰撞**：地面 / 天花板 / 前方管子，取时间到接触最小的 | 真的能飞，实测稳定过 2 根管子 |
| **反射镜** | 把 104 个 LC4 **整群**钳制成同一发放率（= `scripts/loom_transfer.py` 的做法） | 一定看得见触发（实测 17 逃 0 失） |
| **真实视野** | 威胁只落在视野一小块 → 高斯窗**只驱动偏好位置重叠的那批 LC4** | 只有覆盖足够大视野时才躲得掉 |
| **第一人称走廊** | 整面带洞的墙迎面压来（洞的视网膜位置换算成驱动图样） | 驱动/阈值比达 2.87，触发 |

**Flappy 模式为什么现在能飞了（这一版的关键改动）**
之前只把**管子**当威胁，于是苍蝇下落时没有任何东西逼它拍翅 → 直接摔死。
改成"取时间到接触最小的碰撞"之后，**地面逼近本身就是一个货真价实的 looming 刺激**：
往下掉 → 地面在视野里扩张 → LC4 发放 → DNp01 触发 → 拍翅 → 停止下坠。
这形成了一个自稳定的控制回路，同一颗冻结脑、同样零可学参数，就能飞起来。

注意这**不推翻** `ESCAPE.md` §3.8 的结论：§3.8 说的是"一个真实尺寸的局部威胁
覆盖不了足够多的 LC4"，那是关于**躲避**的；而维持高度靠的是地面这个**大面积**逼近物，
恰好能覆盖整个视野。两件事不矛盾，而且合在一起才解释得通为什么
"只把管子当威胁"的版本的 Flappy 全是 0 分。

按**空格**或点画面可以亲自接管拍翅，体感一下这游戏有多难。


**「真实视野」是科学含量最高的一屏。** 右侧那根仪表显示的不是"细胞个数占比"，
而是后端按**每个细胞到 DNp01 的真实突触权重**算出的有效驱动 `Σw·p`
对阈值 `(1−leak)·thr/gain = 0.0604` 的比值，黄线 = 阈值。
把「威胁角尺寸 θ」从 5° 推到 170°，你会看到比值爬过 1.0 的那一刻苍蝇才开始躲；
而**比值 0.93 时它确实不躲** —— 判据是预测性的，不是事后解释。

实测（`scripts/loom_retino_coverage.py`）：

| 视野窗宽 | 计数覆盖率 | Σw·p / 阈值 | DNp01 |
|---|---|---|---|
| 只驱动一半 LC4 | 50% | — | **0 脉冲** |
| 0.5 | 52% | 0.32 | 0 脉冲 |
| 0.7 | 67% | 0.93 | 0 脉冲 |
| 1.2 | — | 1.95 | 3 脉冲，触发 |

> **结论：逃逸指令需要约 2/3 的 LC4 群体被同时动员。真实尺寸的逼近物体达不到，
> 所以按苍蝇真实看到的方式给障碍物，它基本不躲。这是几何问题，不是学习问题**
> —— 也正是 FlappyBird 全社区 0 分的原因。详见 `ESCAPE.md` §3.8。

## 每个数字来自哪里

前端不含任何神经计算：所有发放率、阈值、脉冲都来自
`src/fpv/spiking_brain.py`（LIF 内核）+ `src/fpv/looming.py`（通路/对照/逼近运动学），
和 `scripts/loom_*.py` 那套实验代码**完全同一份**。所以演示里看到的
就是报告 `ESCAPE.md` 里量的那些数。

## 已知限制（演示里也写了，别对外夸大）

- 模型时钟 dt = 20 ms，而真实 GF 通路是 1.4–25 ms，**延迟数字只能定性**。
- LC4 的灵敏度 s50 是外部假设（文献里没找到 LC4 的实测发放率），
  所以它是可调旋钮，演示会改变触发早晚，不改变"有阈值、且由那 102 条边携带"这个结论。
- Flappy 模式分数低是预期结果，全社区的全脑版本都是 0 分。
- 「真实视野」里的视野轴是用 LC4 包围盒中心**方差最大的解剖轴**近似的，
  不是逐个细胞实测的感受野位置；决定阈值的是加权覆盖率（窗宽 0.7 时计数覆盖 67%
  但加权覆盖只有 31% —— 强突触的 LC4 并不都落在视野中心）。
